# Язык .gms — базовый справочник (2D)

Этот файл описывает ядро языка: элементы, которых хватает для подавляющего
большинства интерактивных примеров по школьной и общей математике.
Все имена полей и значения по умолчанию сверены с парсером
`assets/js/gms-compiler.js` — если поле здесь не указано, его, скорее всего,
не существует, и компилятор его молча проигнорирует.

## Общая структура файла

Весь код обёрнут в квадратные скобки. Внутри — необязательное описание и
любое количество объявлений объектов.

```
[
description = "Текст под примером — что делать пользователю"

new Point { name = "A"; pos = (-4, -2); dynamic = true; text = true("A") }
new Line  { name = "ab"; pos = (A, B) }

show axes = true;
show grid = true;
]
```

Правила синтаксиса, на которых чаще всего ошибаются:

- Поля внутри `{ }` разделяются **точкой с запятой**, а не запятой.
- Точка с запятой после последнего поля не нужна, но и не мешает.
- Строки — в двойных кавычках: `name = "A"`.
- Цвет — либо `#rrggbb`, либо не указывать вовсе (см. «Цвета» ниже).
- Координаты — круглые скобки через запятую: `pos = (2, -3)`.
- Ссылка на другой объект — просто его имя без кавычек: `pos = (A, B)`.
- `show ... = ...;` — отдельные команды сцены, они **вне** блоков `{ }` и
  заканчиваются точкой с запятой.

## Цвета, толщины и прочая косметика — важнейшее правило

**Не указывай `color`, `thickness`, `size` и подобные косметические поля
вообще**, если конкретно этот элемент не нужно выделить среди остальных.
У всех них есть значение по умолчанию, которое автоматически подстраивается
под светлую и тёмную тему страницы. Как только цвет задан явно, он
перестаёт подстраиваться — и на одной из тем элемент станет нечитаемым.

Это касается всего: точек, линий, текста, элементов интерфейса, подписей.

Если выделить элемент цветом всё-таки нужно, бери цвета, контрастные
**одновременно** на светлом и на тёмном фоне — например насыщенные синий
`#3b82f6`, оранжевый `#f59e0b`, зелёный `#22c55e`. Не используй чистый
белый, чистый чёрный и очень светлые или очень тёмные оттенки.

## Точка — `new Point`

```
new Point { name = "A"; pos = (-4, -2); dynamic = true; text = true("A") }
```

| Поле | По умолчанию | Смысл |
|---|---|---|
| `name` | — | обязательное, латиницей, по нему на точку ссылаются |
| `pos` | — | координаты `(x, y)` |
| `dynamic` | `true` | можно ли перетаскивать мышью |
| `active` | `true` | участвует ли точка в сцене |
| `text` | нет | подпись: `text = true("A")` |
| `size` | `1` | размер |
| `textSize` | `1` | размер подписи |
| `layer` | `40` | порядок отрисовки, больше — выше |
| `color`, `textColor` | тема | **не задавать без необходимости** |

Столкновения (нужны редко): `collision` (`true`), `collideWithPoints`
(`true`), `collideWithBoundary` (`true`), `collideWithLines` (`false`),
`collideWithFigures` (`false`), `collideWithCircles` (`false`),
`collisionMargin` (`0`), `collisionGroup` (`0`).

Построение точки от других объектов вместо явных координат:
`center`, `over`, `around`, `vertex`, `reflect`, `rotate`, `translate`,
`homothety` — в каждое передаётся имя точки.

## Отрезок — `new Line`

```
new Line { name = "ab"; pos = (A, B) }
```

| Поле | По умолчанию | Смысл |
|---|---|---|
| `name` | — | обязательное |
| `pos` | — | две точки: `(A, B)` |
| `thickness` | `2.5` | толщина |
| `interact` | `true` | реагирует ли на мышь |
| `active` | `true` | участвует ли в сцене |
| `layer` | `10` | порядок отрисовки |
| `color` | тема | **не задавать без необходимости** |

Внимание: поле называется `interact`. Написание `interect` — ошибка,
компилятор такое поле просто не увидит.

## Угол — `new Angle`

```
new Angle { name = "abc"; lock = true }
```

| Поле | По умолчанию | Смысл |
|---|---|---|
| `name` | — | обязательное |
| `lock` | `false` | зафиксировать величину угла (прямой угол и т.п.) |
| `arc` | `true` | рисовать дугу |
| `measure` | `true` | показывать градусную меру |
| `fractions` | `false` | показывать дробью |
| `layer` | `5` | порядок отрисовки |
| `arccolor`, `measurecolor` | тема | **не задавать без необходимости** |

`lock = true` — это то, чем задаётся, например, всегда прямой угол в теме
«Прямоугольный треугольник».

## Знак равенства отрезков — `draw EquallySing`

```
draw EquallySing { name = "eq1"; edges = (ab, cd); type = 1 }
```

| Поле | По умолчанию | Смысл |
|---|---|---|
| `name` | — | обязательное |
| `edges` | — | отрезки, которые помечаются равными |
| `type` | `1` | номер группы равенства |
| `layer` | `80` | порядок отрисовки |
| `color` | тема | **не задавать без необходимости** |

Правило нумерации: первая группа равных отрезков — всегда `type = 1`.
Если в примере есть вторая группа отрезков, равных между собой, но **не**
равных первой группе, — ей даётся `type = 2`, третьей `type = 3` и так
далее. Не начинай со второго типа и не пропускай номера.

## Вектор — `draw Vector`

```
draw Vector { name = "v1"; pos = (A, B) }
```

| Поле | По умолчанию | Смысл |
|---|---|---|
| `name` | — | обязательное |
| `length` | авто | длина |
| `thickness` | тема | толщина |
| `layer` | `70` | порядок отрисовки |
| `color` | тема | **не задавать без необходимости** |

Используй `draw Vector` **только когда нужен именно вектор** — то есть
направленная величина. Обычный отрезок рисуется через `new Line`.
Стрелка рисуется только на конце вектора: не в середине и не на обоих
концах.

| Поле | По умолчанию |
|---|---|
| `name` | — |
| `type` | из полей |
| `thickness` | `1.5` |
| `color` | тема |

## Элементы интерфейса — `new UI`

Доступные типы: `button`, `input`, `number`, `slider`, `select`, `text`.

| Поле | По умолчанию | Смысл |
|---|---|---|
| `name` | — | обязательное |
| `type` | — | один из типов выше |
| `x`, `y` | авто | положение |
| `width`, `height` | авто | размеры |
| `radius` | `4` | скругление углов |
| `stepper` | `true` | стрелки у числового поля |
| `active` | `true` | доступен ли элемент |
| `layer` | `100` | порядок отрисовки |
| `color`, `textcolor` | тема | **не задавать без необходимости** |

Частая ошибка: **действие кнопки не берётся в кавычки**. Это код, а не
строка. Внутри действия следи за парностью скобок и за точками с запятой
между командами.

## Вычисления: функции, `Start` и `Update`

Однострочная функция объявляется на верхнем уровне, вне блоков:

```
func f(x) = x^2 + sin(x);
```

Многострочная — через `Function` (возвращает значение) или `Void`
(ничего не возвращает):

```
Function koren(x) {
  return sqrt(x);
}
```

Два служебных блока задают поведение во времени:

- `Start { ... }` — выполняется один раз при запуске примера;
- `Update { ... }` — выполняется постоянно, на каждом кадре.

```
Start {
  rezultat = 0;
}
Update {
  rezultat = sqrt(vvod);
}
```

Здесь `vvod` — имя поля ввода `new UI`, а `rezultat` — обычная переменная,
которую можно показать через `draw Text` или подставить в подпись.

## График функции — `draw Function`

```
func f(x) = sqrt(x);
draw Function { name = "grafik"; f = "f" }
```

| Поле | По умолчанию | Смысл |
|---|---|---|
| `name` | — | обязательное |
| `f` | — | **имя функции в кавычках**: `f = "f"` |
| `xmin`, `xmax` | `-10`, `10` | границы построения |
| `segments` | `100` | точность (число сегментов) |
| `thickness` | `2` | толщина линии |
| `layer` | `20` | порядок отрисовки |
| `active` | `true` | показан ли график |
| `color` | тема | **не задавать без необходимости** |

Обрати внимание: в поле `f` передаётся **имя** ранее объявленной функции
строкой, а не само выражение. Сначала `func f(x) = ...;`, потом ссылка на
неё.

## Алгебраические темы: что изображать

Если у темы на первый взгляд нечего визуализировать (например «Квадратный
корень»), изображается сама операция с полем ввода: пользователь вводит
число — пример считает и показывает результат.

Схема такая: поле ввода `new UI` с `type = "input"` или `type = "number"`,
переменная-результат, пересчёт в `Update`, вывод результата текстом. К
этому уместно добавить вторую вкладку с графиком соответствующей функции
(см. «Вкладки» ниже) — на одной вкладке вычисление, на другой поведение
функции целиком.

## Кластер — `new Claster`

Кластер — это именованная группа объектов, которую можно показывать и
скрывать целиком. Именно на кластерах делаются вкладки.

```
new Claster { name = "tab1"; elements = (A, B, ab, uglol); active = true }
new Claster { name = "tab2"; elements = (F, osi); active = false }
```

| Поле | По умолчанию | Смысл |
|---|---|---|
| `name` | — | обязательное |
| `elements` | — | список имён объектов через запятую в круглых скобках |
| `active` | `true` | показан ли кластер |
| `interact` | `true` | реагируют ли объекты кластера на мышь |
| `rotate` | `0` | поворот группы целиком |

Обрати внимание: элемент называется `Claster` — именно так, через `a`.

### Вкладки

Вкладки делаются так: каждая вкладка — свой кластер, у активной
`active = true`, у остальных `active = false`. Переключение — кнопками
`new UI` с типом `button`, действие которых меняет `active` у кластеров:
включает нужный и выключает остальные.

Никакого другого способа делать вкладки нет: не создавай отдельные сцены,
не прячь объекты по одному — только кластеры целиком.

Поле `step` у кластера **для вкладок не используется**. Оно предназначено
для пошаговых доказательств и управляется не сценой, а страницей темы
снаружи (аккордеоном описания): кластер со `step` виден только когда
снаружи выбран этот шаг, и никаких кнопок переключения внутри сцены при
этом не появляется. Для вкладок внутри примера используй `active`.

## Параметры сцены

Отдельными командами после объектов:

```
show axes = true;
show grid = true;
```

Прочие параметры сцены задаются так же по имени: `show axis x`,
`show axis y`, `grid size`, `grid color`, `grid adaptive`, `axes color`,
`axes size`, `field width`, `field height`, `field color`, `frame color`,
`frame width`, `boundary color`, `description size`, `description color`,
`description align`.

Как и с цветами элементов: не задавай их, если нет причины — значения по
умолчанию уже согласованы с обеими темами страницы.

## Чек-лист перед выдачей кода

1. Весь код обёрнут в `[ ... ]`.
2. Поля внутри `{ }` разделены точкой с запятой.
3. У каждого объекта есть `name`, имена не повторяются.
4. Ни одного лишнего `color` / `thickness` / `size` — только там, где
   выделение действительно нужно.
5. `type` у знаков равенства начинается с `1` и растёт по группам.
6. `draw Vector` — только для настоящих векторов.
7. Вкладки — только через кластеры и `active`, не через `step`.
8. Все скобки парные, все строки закрыты кавычками.
