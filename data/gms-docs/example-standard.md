# Стандарт интерактивного примера (.gms)

Живой документ: дополняется по мере разбора примеров. Каждый пример на сайте
обязан соответствовать всем пунктам ниже. Синтаксис языка — в `core-2d.md`.

## 1. Интерактивность

Каждый пример обязательно интерактивный: перетаскиваются точки фигуры, вводятся
свои числа в формулу, двигаются ползунки и т. п. Статичная картинка — не пример.
Если придумать взаимодействие трудно, нужно проявить изобретательность, но
интерактивность должна быть.

## 2. Тема (светлая / тёмная)

Любой элемент — точка, линия, подпись, `draw Text`, знак равенства, дуга угла,
кнопка, ползунок — без явного цвета, если он не выделяется цветом специально для
акцента внимания. Тогда цвет автоматически подстраивается под тему страницы.

- Не задавать `color`, `textColor`, `textcolor`, `arccolor`, `measurecolor`
  «для красоты».
- Акцентный цвет допустим, только если он контрастен одновременно на светлом и на
  тёмном фоне (насыщенные `#3b82f6`, `#f59e0b`, `#22c55e`). Чистый белый, чистый
  чёрный, очень светлые и очень тёмные оттенки запрещены.
- Исключение — служебный `color = "transparent"` у вспомогательных невидимых
  линий (см. п. 4).

## 3. Соответствие теме

Объект в примере — ровно тот, что в названии темы, во всей своей общности, и
никакое взаимодействие не может превратить его во что-то другое.

- «Прямоугольный треугольник» — треугольник с заблокированным углом 90°
  (`new Angle { ...; lock = true }`), а не произвольный.
- «Параллелограмм» — произвольный параллелограмм, который можно менять, но нельзя
  сделать непараллелограммом. Не зафиксированная фигура и не произвольный
  четырёхугольник.
- Общность не теряется: если тема — параллелограмм, пример не должен сводиться к
  прямоугольнику или ромбу (они получаются лишь как частные положения).
- Никакое взаимодействие не делает фигуру вырожденной: вершины не сливаются,
  стороны не схлопываются, углы не вырождаются в 0° или 180°. Такой ход отменяется.
- Каждая фигура обязательно оформляется как `new Figure` (многоугольник — из своих
  сторон: `elements = (ab, bc, cd, da)`), даже если отдельные отрезки уже нарисованы.

## 4. Изобретательность

В GMS нет готовых функций под каждую фигуру, но есть инструменты, которых хватает,
чтобы выразить нужное ограничение. Ими нельзя пренебрегать. Примеры приёмов:

- Связь вершин через `Update`: все вершины свободные, при сдвиге одной
  пересчитывается зависимая (`C.pos.x = B.pos.x + D.pos.x - A.pos.x` и т. п.) — см. п. 5.
  Преобразования `translate`/`reflect`/`rotate` делают точку вычисляемой и потому
  неперетаскиваемой — для вершин фигур они не годятся.
- Построенные точки: `construct = median | altitude | bisector` (середина отрезка,
  основание высоты, основание биссектрисы); `reflect`, `rotate`, `homothety`.
- Точка на объекте: `line = "..."`, `circle = "..."`, `graph = "..."` и т. д.
- Невидимая вспомогательная линия (`color = "transparent"` или `active = false`) —
  например, чтобы отметить прямой угол между высотой и продолжением стороны.
- Живые величины: длина отрезка — `ab.length`, мера угла — `angA.measure`,
  форматирование — `format(x, 2)`; выводятся в описание (п. 7).
- Проверки в `Function` (например, `inField(x, y)`, `okShape(...)`) — чтобы
  отменять недопустимые ходы.

- Группы равных углов отмечаются числом дуг (`count = 1, 2, 3` у `draw Angle`),
  прямой угол — всегда одним квадратиком (компилятор делает это сам при любом `count`).

## 5. Интерактивны все определяющие точки

Если фигура задаётся вершинами, перетаскиваются **все** вершины, а не «все, кроме
вычисляемой». Связь между ними поддерживается в `Update`: запоминается предыдущее
положение вершин, определяется сдвинутая, и пересчитываются зависимые (у
параллелограмма — противоположная вершина, соседние стоят на месте).

- У таких точек ставится `pauseOnDrag = false`, иначе `Update` на время
  перетаскивания замирает, и фигура «догоняет» только после отпускания.
- Ни одну точку — ни перетаскиваемую, ни пересчитанную — нельзя вывести за поле.
- **Ограничения плавные.** Недопустимый ход не отменяется целиком (точка «прилипает»),
  а обрезается: вершина проходит допустимую часть хода, а остаток движения
  раскладывается по осям — так она скользит вдоль границы поля, вдоль другой точки и
  вдоль любого ограничения формы. Это касается и случая, когда в границу упирается не
  сама точка, а зависимая от неё.
- Путь хода проверяется по промежуточным точкам, а не только по конечной: иначе при
  быстром движении точка «перепрыгнет» узкую запрещённую зону (например, вырожденное
  положение) и фигура вывернется.
- Вершина, которую двигают, определяется по **наибольшему** смещению за кадр
  (пересчёты дают у остальных погрешность ~1e-15, простое `!=` ловит их ложно).
- Фигура (`new Figure`) перетаскивается целиком за пустое место внутри неё — это
  поведение по умолчанию, `interact = false` не ставить.
- Перетаскивание фигуры целиком (все вершины сдвинуты на один вектор) обрабатывается
  отдельно — как перенос, а не как ход одной вершины при уже сдвинутых соседях.
- Граница поля для центров точек — `fieldMaxX` / `fieldMaxY` (движок держит точку
  внутри поля целиком, с отступом в её радиус; число зависит от ширины холста, поэтому
  не зашивается в код).
- В конце `Update` — страховка: если кадр всё же дал нарушение (не параллелограмм,
  точка вне поля), все вершины возвращаются в последнее корректное положение.
- Проверка перед выдачей — фаззинг: десятки случайных резких ходов вершинами и фигурой
  целиком с проверкой инварианта после каждого.

Готовая схема — `data/examples/parallelogram.gms` (функции `ok`, `reach`, `slide`).

## 6. Вкладки — только кластеры

Если теме нужно несколько вкладок, каждая вкладка — свой `new Claster`, а
переключение — кнопки `new UI { type = button }`, которые меняют `active` у
кластеров. Ручное скрытие каждого элемента по отдельности запрещено.

```
new Claster { name = "tabSides"; elements = (...); active = true }
new Claster { name = "tabDiag";  elements = (...); active = false }
new UI { name = "btnSides"; type = button; label = "Стороны и углы";
         action = "tabSides.active = true; tabDiag.active = false" }
```

- Общие для всех вкладок объекты (сама фигура) в кластеры не входят.
- Кнопка вкладки также ставит переменную `tab`, по которой `Update` выбирает текст
  описания для этой вкладки (см. п. 7).
- Поле `step` у кластера для вкладок не используется (оно для пошаговых
  доказательств).

## 7. Текст — в описание, на поле только подписи

Описание — про математику, а не про управление. Не писать «перетаскивайте точки»,
«фигура остаётся параллелограммом» и т. п.: интерактивность — привычная фишка сайта.
Подсказка по управлению допустима, только если оно неочевидно, и тогда — в самом
конце описания.

На поле остаются только подписи, которым там действительно место: имена точек,
меры углов, короткие метки объектов. Пояснения, формулы, суммы, значения величин —
в описание под полем. Описание живое: `description = "{info}"`, а строка `info`
собирается в `Update` (разная для каждой вкладки, с `**жирным**` и `\n\n` между
абзацами).

## 8. Поле: масштаб, граница, сетка

- **Масштаб.** При запуске фигура занимает большую часть поля (примерно 60–70 % по
  ширине). Масштаб задаётся размером поля в единицах: `field width` / `field height`
  (по умолчанию 50 × 30 — для геометрии слишком мелко; для фигуры порядка 10 единиц
  подходит `field width = 20; field height = 12;`).
- **Граница поля видна** практически всегда: `show boundary = true;` — это та самая
  стена, в которую упираются точки.
- **Сетка и оси** — только там, где они по смыслу нужны (графики функций,
  координатная плоскость, векторы в координатах). В чистой геометрии их нет.

## Технические требования

- Пример компилируется `gms-compiler.js` без ошибок и без предупреждений в консоли.
- Пример проверен в обеих темах, в том числе при переключении темы на лету, и
  проверены «злые» сценарии: вывести точку за поле, столкнуть вершины, выродить фигуру.
- Столкновения точек — по смыслу. Точки, которые должны проходить друг через друга
  или через неподвижную отметку (числа на прямой, точка на графике через вершину),
  получают `collideWithPoints = false`; вспомогательные неперетаскиваемые точки
  (проекции, отметка нуля) — `collision = false`.
- Числа в тексте — с настоящим знаком минус «−», отрицательные в выражениях — в
  скобках: |−3,0 − (−6,0)|.
- Для алгебраических тем сетка и оси включаются только на вкладке с графиком: сетку
  даёт сам `draw Function { grid = true }`, поэтому она прячется вместе с кластером.
